# 사용자·권한 관리 (feature/access-control)

## 첫 실행 및 업그레이드

기존 단일 실행파일·SQLite·자동 시작 구조를 유지한다. 마이그레이션 006은
인증/권한/세션/감사 테이블만 추가하며 기존 프로세스와 실행 계정 비밀번호를
삭제하지 않는다. 기존 프로세스는 `기존 프로세스` 그룹에 관리자 전용으로
이관한다. 자동 시작은 관리자의 브라우저 로그인과 무관하게 기존대로 동작한다.

첫 접속 `/login`에서는 **OS 관리자 인증** 또는 **SpawnPoint 자체 계정**을
선택한다. 토큰 파일을 직접 찾는 절차는 기본 경로가 아니다.

- Windows: 서버 Administrators 계정과 실제 OS 비밀번호를 확인해 최초 관리자에
  연결한다. Windows가 발급한 토큰의 활성 관리자 SID를 검사하며 UAC 분리 토큰은
  연결된 토큰도 확인한다. 임의 헤더/사용자명/그룹 이름만 믿지 않는다.
- Linux: non-root 서버에서 PAM(`su`) 인증 후 UID 0 또는 **root 셸을 시작할 수 있는
  sudo 정책**을 확인한다. `sudo -l -u root /bin/sh`의 실제 정책 판정이 필요하고
  sudo/wheel 그룹명이나 특정 명령 하나의 sudo 허용만으로 관리자를 부여하지 않는다.
  root 셸은 실제로 실행하지 않는다. 비밀번호는 전용 파이프로만 넘기고 저장하지 않는다.
- 두 방식 모두 최초 계정이 없는 동안만 가능하며 모든 초기화 경로가 같은 잠금과
  SQLite revision 조건으로 중복 생성을 차단한다. 기존 계정의 복구/승격 기능이 아니다.

자체 관리자 계정은 **서버가 실행 중일 때** 서버 로컬 터미널에서 만든다.
Windows는 관리자 권한 PowerShell, Linux는 sudo/root 권한으로 실행한다.

```powershell
.\spawnpoint.exe setup status
.\spawnpoint.exe admin init
.\spawnpoint.exe setup token
```

```sh
./spawnpoint setup status
sudo ./spawnpoint admin init
sudo ./spawnpoint setup token
```

`admin init`은 ID/표시 이름/12자 이상 비밀번호를 묻고 비밀번호 입력은 숨긴다.
`setup status`는 **실행 중인 서버에서 조회한 실제 DB 경로·토큰 위치·초기화 상태**를
표시하며 토큰 원문은 출력하지 않는다. `setup token`만 OS 관리자에게 원문을 명시적으로
표시한다. CLI가 다른 작업 폴더에서 실행되어도 DB를 추측하거나 새 DB를 만들지 않는다.
포트가 다르면 각 명령 뒤에 `--url http://127.0.0.1:포트`를 붙인다. 웹 화면에도 실제
리스너 포트에 맞춘 명령이 표시된다. 서버 미실행 시 먼저 실행하라는 오류로 종료한다.

자동화는 `admin init --login ID --name NAME --password-stdin`으로 비밀번호 한 줄을
표준입력에 전달한다. 비밀번호를 명령행 인수에 넣는 옵션은 없다. 관리자 생성 CLI는
보호된 로컬 토큰으로 서버를 확인하고, 계정 내용에 바인딩된 HMAC으로 요청을 인증한다.
원문 토큰을 HTTP로 전송하지 않으며 원격 주소/프록시 환경변수/리다이렉트는 거절한다.

기존 토큰 웹 초기화는 자체 계정 탭의 보조 메뉴에 남긴다. 토큰 파일은
`<SPAWNPOINT_DB_PATH>.setup-token`이며 최초 계정 생성 후 제거한다. 보호된 파일을
만들지 못해도 OS 관리자 인증은 계속 사용할 수 있고 `setup status`가 오류를 안내한다.
원격 비로그인 응답에는 DB·토큰 절대 경로 또는 토큰 원문을 공개하지 않는다.
환경변수 `SPAWNPOINT_SETUP_TOKEN` 방식도 유지한다. 이 경우 CLI에는 같은 환경변수를
설정해야 하며 파일이 자동 생성되었다고 안내하지 않는다.

접속은 직접 localhost 또는 HTTPS를 사용한다. 같은 서버의 Caddy가
`reverse_proxy 127.0.0.1:7527`로 전달하는 HTTPS는 **추가 환경변수 없이 인식**한다.
실제 TCP 연결이 루프백이고, 단일 `X-Forwarded-Proto: https`, 요청 Host와 일치하는
`X-Forwarded-Host`, 유효한 `X-Forwarded-For`가 있을 때만 자동 인정한다.
로그인·최초 설정·세션 쿠키·출처 검사·지정 계정 실행은 같은 판정 함수를 사용한다.

로컬 OS 프로세스와 프록시는 신뢰 경계 안에 있다. 프록시는 외부에서 받은 전달
헤더를 덮어써야 하며 Caddy 기본 동작이 이를 수행한다. 다른 호스트의 연결은
헤더가 같아도 신뢰하지 않는다. 일반 원격 HTTP 및 프록시의 HTTP 프런트엔드도
차단한다. 전달 요청에는 Host가 localhost여도 직접 로컬 예외를 주지 않는다.
`SPAWNPOINT_TRUST_LOOPBACK_PROXY=0`은 자동 인식을 명시적으로 끄며, 기존 `1`은
스킴 헤더만 전달하는 로컬 프록시를 위한 명시적 호환 옵션으로 유지한다.
브라우저 인증서 신뢰 설정을 변경하거나 인증/권한 검사를 생략하지 않는다.

기존 `SPAWNPOINT_API_TOKENS`는 사용자/범위 없는 인증이므로 이 게이트웨이를
우회하지 못한다. 기존 연동은 관리자가 사용자 소유·프로세스 그룹 범위를 갖는
새 API 토큰으로 교체해야 한다. 이전 토큰을 묵시적으로 관리자 토큰으로
승격시키지 않는다. `/spawn`은 현재 관리자 웹 세션 전용이며 새 scoped 토큰의
대상은 `/processes*`이다. 배포 전 연동 사용처를 확인한다.

## 로그인

* **OS 계정**: 서버 OS가 인증하는 계정. 관리자가 먼저 해당 신원을 연결하고
  역할을 부여해야 한다. 사용자 ID 문자열만 같다고 자체 계정과 합치지 않는다.
  사용자 추가·편집에서 별도 사용자 ID나 자체 비밀번호를 입력하지 않는다. OS 계정
  식별자만 받으며 내부 ID는 자동 생성한다. Windows SID/Linux UID 중복 연결은
  거절한다. 기존 연결의 내부 ID·권한·그룹은 그대로 유지하며, 사용자 ID 입력은
  SpawnPoint 자체 계정에서만 필수다.
* **SpawnPoint 계정**: 별도 사용자 DB, salted PBKDF2-HMAC-SHA256 600,000회.
* **비로그인**: 기본 꺼짐. 관리자가 명시적으로 공개한 그룹/프로세스의 상태만
  조회한다. 로그 공개는 별도 설정이며 생성·편집·실행·자격정보 사용은 불가하다.

Windows OS 로그인은 LogonUserW(NETWORK) 결과의 SID를 등록된 신원과 비교한다.
프로세스 실행이나 권한 상승을 하지 않는다. 로컬/도메인 계정과 OS 로그온 정책을
따른다. Windows Hello PIN은 계정 비밀번호가 아니다.
Linux는 non-root 서비스에서 util-linux `/usr/bin/su`의 PAM 인증·계정 검사를
거친 뒤 고정 명령 `/usr/bin/id -u`로 신원을 확인한다. 임의 명령/로그인 셸 시작
스크립트를 실행하지 않는다. 비밀번호는 일회성 표준입력으로만 넘긴다.
root 서비스는 비밀번호 검증을 우회할 수 있어 OS 로그인 기능을 제공하지 않는다.
정적 Go 빌드의 Linux 신원 조회는 로컬 passwd 사용자 기준이다. LDAP/NSS 사용자나
사용자 정의 PAM 정책은 별도 검증이 필요하다. OS 계정 삭제·UID 재사용 시 연결
정보도 관리자가 정리해야 한다.

OS 로그인 비밀번호는 보관하지 않는다. 로그인 신원과 프로세스 `run_as`는 별개다.
관리자 권한을 OS 관리자 여부로 자동 부여하지 않는다.
**Kerberos/Negotiate 등 비밀번호 없는 자동 SSO는 이 버전에 구현하지 않았다.**
미지원 옵션은 비활성 상태로 표시하고 헤더의 사용자명을 신뢰하는 우회는 없다.
브라우저 세션 유지와 SSO를 혼동하지 않는다.

## 역할과 대상 권한

| 역할 | 조회·로그 | 실행·중지·재시작 | 편집 | 생성 | 삭제·권한·사용자 관리 |
|---|---|---|---|---|---|
| 뷰어 | 대상 허용 시 | 불가 | 불가 | 불가 | 불가 |
| 참조자 | 대상 허용 시 | 대상 허용 시 | 대상 허용 시 | 불가 | 불가 |
| 개발자 | 대상 허용 시 | 대상 허용 시 | 대상 허용 시 | 그룹에서 생성 허용 시 | 불가 |
| 관리자 | 전체 | 전체 | 전체 | 전체 | 전체 |

프로세스 그룹은 하나에 소속한다. 그룹 ACL이 신규/기존 프로세스에 자동 상속된다.
개별 프로세스 예외는 같은 대상의 규칙만 교체한다. 사용자 직접 설정이 우선하고,
여러 사용자 그룹 간에는 명시적 거부가 우선하며 그 외에는 허용의 최대 범위를
사용한다. 마지막에 역할 상한과 편집 보호를 적용한다. `설정 없음`은 상속/기본
거부, `접근 불가`는 명시적 거부다. 모든 API에서 서버가 최종 판정한다.

일괄 이동/예외 초기화는 최대 500개 프로세스에 대해 먼저 서버에서 영향도를
계산한다. 확인한 revision과 현재 revision이 다르면 409로 거절한다. 정책 변경과
감사 기록은 같은 SQLite 트랜잭션에 저장한다. 사용자 그룹 멤버 변화는 즉시
재평가하며, 역할·정지·비밀번호·인증 신원 변경은 세션과 API 토큰을 무효화한다.
로그인 가능한 마지막 관리자의 삭제·정지·강등·인증 비활성화는 거절한다.

지정 OS 실행 계정을 사용하는 프로세스의 명령·경로·환경변수는 관리자만 편집한다.
기존 자격정보를 모르는 사용자가 명령을 바꿔 다른 OS 권한을 사용하는 것을 막는다.
일반 프로세스도 별도로 편집 보호할 수 있고 실행은 위임할 수 있다.

**이 권한 시스템은 OS 샌드박스가 아니다.** 임의 명령을 편집/생성하도록 허용하면
그 실행 OS 계정이 접근하는 파일·DB·네트워크도 사용할 수 있다. 실행파일/스크립트/
설정 파일을 외부에서 바꾸는 경로까지 앱 ACL이 차단하지 못한다. 편집·생성 권한은
신뢰하는 운영자에게만 부여하고, 상호 불신 사용자는 OS 계정·파일 권한·별도 인스턴스/
컨테이너 등으로 격리해야 한다. 비로그인 로그 공개도 토큰·개인정보 누출을 확인한
그룹에서만 활성화한다.

## 세션·감사·토큰

세션 쿠키는 HttpOnly/SameSite=Strict, HTTPS에서는 Secure이며 서버에는 원문 대신
랜덤 토큰의 SHA-256만 저장한다. 브라우저에서 받은 CSRF 토큰도 모든 변경 요청에서
검사한다. idle 15/30/60/120분, 절대 12시간, 사용자당 최대 10세션이다. 로그/목록
주기 조회는 idle을 연장하지 않는다. 실제 사용자 조작은 heartbeat로 갱신한다.
로그인은 계정당 5회/5분, 실제 TCP peer당 50회/5분으로 제한하며 SQLite에 저장한다.
외부 헤더로 rate limit 신원을 조작할 수 없다. 프록시 뒤 여러 사용자는 peer 제한을
공유하므로 대규모 배포 시 신뢰 프록시 정책을 별도 설계해야 한다.

관리자 민감 설정은 기본 10분 이후 비밀번호 재확인을 요구한다. API 토큰은
사용자 소유/한 프로세스 그룹/최대 작업 수준/생성 여부/만료일의 교집합으로 제한하며
값은 생성 직후 한 번만 보여 준다. 평문은 저장하지 않고 관리 API에는 사용할 수 없다.
로그인·정책·실행 요청/결과·거부를 기록한다. 감사 화면/내보내기는 최근 500건이고
DB에는 전체 기록을 보존한다. 감사 DB/백업 보존 용량은 운영자가 관리해야 한다.
OS 비밀번호·로그인 비밀번호·토큰 원문·명령의 환경변수는 감사 기록에 남기지 않는다.

## 화면 언어 및 사용자 등록

로그인·최초 관리자 설정에서 한국어 / English / 日本語를 선택할 수 있다.
로그인 후 모든 관리 화면과 프로세스 화면에도 같은 언어 선택이 표시된다.
언어 선택은 브라우저의 `localStorage`에 UI 언어 코드만 저장하며,
세션·토큰·비밀번호·인증 방식과 무관하다. 저장된 언어가 없으면 브라우저의
지원 언어를 사용하고, 지원하지 않으면 한국어로 표시한다.

사용자 추가 흐름은 로그인 방식 → 이름/계정 → 역할/상태 → 사용자 그룹(존재 시)이다.
OS 계정은 사용자 ID나 자체 비밀번호를 입력하지 않고 OS 계정 식별자만 입력한다.
SpawnPoint 자체 계정은 사용자 ID/비밀번호가 필요하다. 암호화·권한·서버 검증은
기존 동작을 유지한다. 불필요한 설명 상자와 빈 그룹 영역은 표시하지 않는다.

## 화면·API

로그인 `/login`, 프로세스 `/`, 내 계정 `/account`, 관리자 `/admin` 및
`/admin/users`, `/admin/groups`, `/admin/permissions`, `/admin/security`, `/admin/audit`.
단일 실행파일에 승인 시안 스타일을 내장하며 미리보기용 역할 전환과 샘플 데이터는 없다.

인증 API: `/auth/me`, `/auth/setup`, `/auth/login`, `/auth/logout`, `/auth/reauth`,
`/auth/password`, `/auth/revoke-sessions`, `/auth/heartbeat`.
권한 API: `/api/access/state`, `/api/access/preview`, `/api/access/admin`.
기존 프로세스 API는 `group_id`, `protected`, `capabilities`를 추가하며 서버 필터링한다.
기존 명령 저장/실행 분리와 환경변수·작업 경로·자동 시작·OS 실행 계정은 유지한다.

`tools/test-access-api.py`, `tools/test-run-as-service.py`, `tools/test-access-browser.py`.
실제 서비스 검사는 GitHub의 일회용 runner에서만 실행하며 기존 설치가 있으면 중단한다.
브라우저 검사는 CI에서 실제 HTTP/cookie로 수행한다. 제한된 로컬 환경의 선택적
브리지 모드는 레이아웃/동작 확인용이며 네이티브 브라우저 보안 검증을 대체하지 않는다.
## 프로세스 편집창의 그룹 변경

관리자는 기존 프로세스 편집창에서 그룹을 직접 선택한다. 저장 또는 저장 후 재시작을
누르면 서버가 계산한 그룹 변경 영향을 확인하고 적용한다. 취소/Escape는 입력을
유지하며 저장·그룹 변경·재시작을 수행하지 않는다. 개별 예외와 공개 설정은 유지한다.
관리자가 아닌 사용자와 API 토큰은 기존 프로세스의 그룹을 이동할 수 없다.

PUT /processes/{id}의 group_id 변경에는 미리보기의 revision이 필요하다. 오래된
revision, 미등록 그룹, 재인증 필요 상태는 명령을 변경하기 전에 거절한다. 명령 저장
실패 시 그룹을 이동하지 않는다. 명령 저장 후 권한 저장만 실패한 경우 원래 그룹을
유지하고 부분 저장 오류를 명시하며 재시작을 요청하지 않는다. 여러 프로세스의 일괄
이동은 기존 경로를 그대로 사용한다.
