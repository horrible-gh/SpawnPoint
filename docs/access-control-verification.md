## 이번 재개 작업에서 해결한 회귀

1. Windows 일반 실행 뒤 지정 계정 실행이 동일한 공유 Job Object 계층에
   배정되면서 거부되던 문제를 수정했다. 지정 계정 실행마다 독립적인 종료 보호
   Job Object를 유지한다. 프로세스 전체 종료 후 자원을 회수하며 서버 종료 시
   하위 프로세스 종료 보호도 유지한다. 실제 혼합 계정 API 실행 및 별도 네이티브
   종료·자원 회수 시험을 통과했다.
2. Windows에서 작은 요청 본문이 남은 채 HTTP/1 연결을 닫을 때 거부/삭제 응답이
   연결 초기화로 유실되던 문제를 수정했다. 최대 64KiB·수신 5초 제한으로 본문을
   먼저 읽고 인증·실행 전에 읽기 제한시간을 초기화한다. 요청을 재전송하거나
   권한·CSRF 검사를 완화하지 않았다. 지연 전송 본문과 명시적 403 회귀도 검사한다.
3. 프로세스 등록 API가 기존의 전체 process 응답을 유지하도록 보완했다. 내부의
   정식 응답 생성기를 재사용하고 조회와 동일한 권한·비밀값 필터를 적용한다.

## 제공 기능과 경계

OS 계정 ID/PW 로그인과 SpawnPoint 자체 계정 로그인은 모두 구현했다.
**Kerberos/Negotiate 등 비밀번호 없는 자동 SSO는 미구현이다.** 이를 지원하는
것처럼 표시하지 않으며 관련 옵션은 비활성화한다. 브라우저 세션 유지는 SSO가 아니다.

검증은 GitHub의 일회용 Windows Server 2025 및 Ubuntu runner에서 수행했다.
사용자 운영 서버, 모든 Windows 도메인 정책, LDAP/NSS 및 사용자 정의 PAM 구성을
검증한 것은 아니다. Linux OS 로그인은 non-root 서비스와 로컬 계정 기준이다.
로그인 신원과 명령의 OS 실행 계정은 별도로 관리한다.

이 기능은 애플리케이션 접근 제어이며 OS 샌드박스가 아니다. 임의 명령 생성·편집
권한은 신뢰하는 사용자에게만 부여해야 한다. 상호 불신 사용자는 OS/인스턴스
차원의 격리가 필요하다.

## 시험 적용 전 확인

- 운영 DB·로그·실행 계정 암호화 키를 백업하고 별도 DB/포트에서 먼저 확인한다.
- 최초 `/login`에서 `<SPAWNPOINT_DB_PATH>.setup-token`의 일회용 토큰으로
  관리자를 생성한다. 기본 관리자 ID/PW는 만들지 않는다.
- 마이그레이션은 기존 명령/자동 시작/암호화된 실행 계정을 삭제하지 않는다.
  기존 명령은 관리자 전용 기본 그룹으로 이관한다.
- 이전 전역 `SPAWNPOINT_API_TOKENS`는 권한을 우회하지 못한다. 연동은 관리자
  페이지에서 발급한 사용자·프로세스 그룹 범위의 새 토큰으로 교체해야 한다.
- 원격 로그인은 HTTPS를 사용하고 비로그인은 기본 비활성이다.
- 상세 구성과 제한은 [access-control.md](access-control.md)를 따른다.
