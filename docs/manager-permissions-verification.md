## 구현

뷰어 / 참조자 / 개발자 / 매니저 / 관리자의 5단계 역할이다. 역할은 최대 권한이며, 실제 접근은 사용자 또는 사용자 그룹에 부여한 대상 권한으로 제한한다.

- 생성: 개발자·매니저에게 그룹의 생성 권한이 명시적으로 있어야 한다.
- 삭제: 매니저에게 해당 그룹/프로세스의 삭제 권한이 명시적으로 있어야 한다. 프로세스별 예외와 명시적 거부를 적용한다.
- 편집·삭제 보호 또는 지정 OS 실행 계정이 설정된 프로세스는 관리자만 삭제할 수 있다.
- 매니저는 사용자·그룹·권한 관리, 그룹 이동, 실행 계정 변경 등 관리자 기능을 얻지 않는다.
- API 토큰에는 삭제 권한을 추가하지 않았다. 소유자가 매니저라도 토큰 삭제 요청은 거절한다.
- 이전 저장 데이터의 삭제 플래그 누락은 false다. 기존 계정의 역할, 내부 ID, 그룹, 권한, 등록 프로세스를 자동 변경하지 않는다.

권한 UI는 접근 수준 선택과 별도 생성/삭제 스위치를 가진 대상별 카드로 정리했다. 역할 제한을 표시하고 반복 안내를 줄였다. 재인증 창은 레이블·전체 너비 비밀번호 입력창을 세로 배치하고 버튼 영역을 정리했다. 한국어·영어·일본어와 모바일 레이아웃을 지원한다.

## 적용

업데이트한 소스로 재빌드하고 실행파일을 교체한 뒤 SpawnPoint를 재시작한다. DB를 지우거나 기존 사용자를 다시 등록할 필요는 없다.

사용자를 매니저로 지정한 다음, 프로세스 권한에서 대상 그룹의 사용자/그룹 규칙에 필요한 생성·삭제를 각각 허용하고 변경 영향을 확인하여 적용한다. 매니저 역할만 부여해도 삭제가 자동 허용되는 구조는 아니다.
